# 01 项目全景与版本演进

> 本文回答「这三个目录到底是什么关系、谁服务谁、按什么顺序演进」。术语以 `README.md` 的澄清表为准。

---

## 一、项目一句话

给 DNF 适配**手柄映射 + 震动反馈**：游戏进程内的采集 DLL 只读监听战斗事件（命中/受击/暴击/DOT/死亡/评分/移动…），写进命名共享内存；外部宿主软件（Rust）读事件、跑震动算法、用 XInput 驱动手柄马达。**游戏本体一个字节不改，删 DLL 即完全还原。**

这套东西同时服务**两个年代完全不同的客户端**，因此才有了「新老两套 DLL」：

| | 新版体系 | 老版体系 |
|---|---|---|
| 游戏客户端 | 90US 新版 DNF（32 位，无壳） | ACT1 老客户端（LMA1S-release 2008，Themida+TerSafe） |
| 采集 DLL | `DfoVibration.dll` | `DfoVibration_OLD.dll` |
| 进游戏方式 | 官方 `us_extend_dll\` 自动加载（或注入） | 无官方机制 → Loader/代理/宿主内置注入 |
| 参数归宿 | DLL ini + 宿主 GUI | 全部宿主 GUI（零 ini） |
| 采集哲学 | 轻 hook、重轮询、聚合冲刷、敢调用游戏函数 | 语义精确 hook 逐条直发 + 纯只读轮询，绝不调用游戏函数 |
| 对应目录 | `1.5版\`、`V3版本\` | `DfoVibration_OLD\` |

## 二、三个原始目录的定位

### 1. `<1.5版目录>`（新版 90US 完整产品包）
**新版客户端（90US）的完整产品包**。虽然目录名带「1.5 版」，它服务的是**新**客户端——这里的 1.5 指**产品版本号**，不是客户端年代。内容：
- `DfoVibration.dll` + `DfoVibration.ini`（采集 DLL，放 `us_extend_dll\`）；
- `SorahkDFO.exe` 及多个补丁版（宿主，Rust/egui，含连发映射 + 震动设定 + 全职业预设）；
- `DLL源码\`（新版 DLL C 源码）、`SorahkDFO源码\`（宿主 Rust 源码）；
- `开发文档\`（总览/震动规范/职业预设/UI 规范/会话恢复存档）、`研究文档\`（评分/事件/镜头/背击等逆向合集 + 377 份 IDA 原始报告）；
- `rankdiff-plugin(废弃方案)\`（评分难度插件，废弃）。

### 2. `<OLD研究仓>`
**ACT1 老客户端适配研究仓**。因为老客户端没有任何插件挂载机制，这里从零做了：
- `DfoVibration_OLD.dll`（老版采集 DLL，v6→v13.39 迭代）+ `DfoVibration_OLD_Loader.exe`（注入器）+ 代理 DLL 方案；
- `docs\`（**权威交接文档 + 46 篇阶段报告**，每篇一个课题的完整证据链）；
- `数据分析结果\`（133 份 `sa_*` 证据文件）、`work\`（capstone 流水线 + IDA 副本 + 判定器）、`IDA分析脚本\`、`release_backup\`（历代 DLL 备份）。

### 3. `<V3目录>`（宿主主程序新一代）
**宿主主程序的新一代（DfoVibration-V3，「新UI版」）**。关键事实：
- 它 `DLL源码\` 与 1.5 版**逐字节相同**（md5 已验证）→ **DLL 没变，变的是宿主**；
- 宿主重构：新 UI（侧边栏设计系统、手柄可视化页、极简模式、白名单页）、稳定性体系（v1.6 panic 兜底/背压合并）、**S1/S4+ 双震动路线**、**内置 auto_inject**（免 Loader 注入老 DLL）、群怪聚合/命中限频/脉冲落地等高级算法；
- 目录里同时存在 `DfoVibration.dll`（新版采集）与 `DfoVibration_OLD_dll.log`（老版采集日志）→ 实际联调时**同一套 V3 宿主两端都在用**（因为协议一致）。

## 三、版本谱系（谁从谁派生）

```
                    ┌──────────────────────────────────────────────┐
                    │  DfoVibration 1.5 版（新版 90US 产品）        │
                    │  DfoVibration.dll + SorahkDFO v1.5/v1.6 宿主 │
                    └───────────────┬──────────────────────────────┘
                                    │ 骨架复用（worker 1s + collector 6ms、
                                    │ 协议 vib_protocol.h、stub/trampoline 引擎）
                                    ▼
        ┌───────────────────────────────────────────────┐
        │  DfoVibration_OLD（ACT1 老客户端适配研究仓）   │
        │  DfoVibration_OLD.dll + Loader/代理 + 46 报告  │
        │  复用 1.5 的 SorahkDFO 宿主（协议一致）        │
        └───────────────────────────────────────────────┘
                                    │
                                    │ 老方案语义（通道拆分/合成式/量纲归一/
                                    │ 重映射/分通道窗/聚合治理）移植进宿主
                                    ▼
        ┌───────────────────────────────────────────────┐
        │  DfoVibration V3（宿主新一代）                 │
        │  新 UI + 稳定性 + S1/S4 双路线 + auto_inject   │
        │  DLL 源码 = 1.5 版同一份（md5 相同）           │
        └───────────────────────────────────────────────┘
```

**三个 DLL 的关系**：
- `1.5版\DLL源码\` = 源（新版采集 DLL）；
- `V3\DLL源码\` = 同一份（逐字节相同）；
- `DfoVibration_OLD\DLL源码\` = 从 1.5 骨架派生的重写系（`hooks→hooks_old`、`dfovib→dfovib_old`，新增 Loader/代理/`vib_protocol_old.h`）。

**协议是三者互通的枢纽**：`common/vib_protocol.h` 两版逐字节相同，共享内存 `Local\DfoVibrationShm` 与 `VEV_*` 事件枚举一致 → 任意 DLL 都能喂同一套宿主。

## 五、组件关系图（一张图看懂数据流与部署）

```
┌─────────────────── 游戏进程 ────────────────────┐        ┌────────── 宿主进程 ──────────┐
│  DNF.exe                                        │        │  SorahkDFO / V3 (Rust)       │
│   ├─ 新版: us_extend_dll\DfoVibration.dll        │        │                              │
│   │        (或宿主 auto_inject)                  │        │  vibration.rs:               │
│   └─ 老版: DfoVibration_OLD.dll                  │        │   读共享内存 → 引擎合成      │
│            (Loader / 代理 / 宿主 auto_inject)    │        │   → XInputSetState           │
│            │                                     │        │                              │
│            │ hook + 轮询（只读）                 │        │  GUI: 连发/震动/职业预设     │
│            ▼                                     │        │  Config/Vibration/JobVibration│
│      共享内存 Local\DfoVibrationShm ─────────────┼───────▶│                              │
│      (VibShm + 256KB 环形队列, CAS)              │        │  → Xbox 手柄马达 L/R         │
└──────────────────────────────────────────────────┘        └──────────────────────────────┘
```

- **同一台机器可同时部署两套**（V3 目录里既有 `DfoVibration.dll` 又有 `DfoVibration_OLD_dll.log` 即证据）；
- 哪套 DLL 进哪个游戏进程，由部署位置/注入目标决定，宿主按共享内存 `gamePid` 区分；
- 参数与算法全在宿主侧，换 DLL 不动宿主（协议不变）。
