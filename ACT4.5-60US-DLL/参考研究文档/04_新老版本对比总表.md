# 04 新老版本对比总表

> 对比对象与口径：
> - **新版** = 90US 新客户端 + `DfoVibration.dll`（源码见 1.5 版/V3 的 `DLL源码\`，两者逐字节相同）
> - **老版** = ACT1 老客户端 + `DfoVibration_OLD.dll`（`DfoVibration_OLD\DLL源码\`，v13.39）
> - 宿主是同一套 SorahkDFO（1.5/v1.6 → V3），协议互通，故「宿主差异」单列一节。
> - 骨架来自 `DfoVibration_OLD/docs/阶段报告/40_新旧版架构完整对比.md`（2026-09-07），并按 V3 现状（HANDOFF 2026-09-09）更新。
> - ⚠ **两版地址体系完全不同，绝不可混用**（不同客户端、不同加密体系）。

## 一、总览

| 维度 | 新版（90US） | 老版（ACT1） |
|---|---|---|
| 目标客户端 | 新版 DNF（32 位，无壳，主段 R/W/X） | LMA1S-release 2008（x86，Themida+TerSafe 双加密，导入表被壳销毁） |
| DLL 文件 | `DfoVibration.dll`（89,088 B） | `DfoVibration_OLD.dll`（约 71 KB） |
| DLL 源码 | `dfovib.c` + `hooks.c` + `hooks.h` + `hooks_asm.s` | `dfovib_old.c` + `hooks_old.c` + `hooks_old.h` + `hooks_old_asm.s` + `vib_protocol_old.h` |
| 挂载方式 | **官方 `us_extend_dll\` 自动加载**（启动器调导出 `DfoVibrationLoaded`）；或 LoadLibrary+`VibPluginLoaded` | **无任何自动加载机制** → Loader 远程注入 / 代理 DLL 侧加载 / V3 宿主内置 auto_inject |
| 额外组件 | 无 | `DfoVibration_OLD_Loader.exe`、`version.dll`/`dinput8.dll` 代理、注入库 |
| 参数归宿 | DLL 自身 `DfoVibration.ini`（enabled/autostart/gain 等，500ms 热加载）+ 宿主 GUI | **零 ini，全归宿主 GUI**（60 参数槽，用户铁律） |
| 线程模型 | worker（1s 延迟，管装卸/ini/自检/拉起面板）+ collector（6ms） | 同构（骨架直接源自 1.5，注释自证） |
| 共享内存 | 同名 `Local\DfoVibrationShm`，VibShm 单块 | 同名，`sizeof(VibShm)+VIB_RING_SIZE` 独立扩展区 |
| 协议 | `common/vib_protocol.h`（VEV_* 0-25） | 同一份协议 + `vib_protocol_old.h` 扩展（VEVO_* 26-36，已废弃不用） |
| 日志 | 2MB 自动轮转 `.old` | v13.39 起才加 2MB 轮转（此前手动清） |
| 采集哲学 | **轻 hook、重轮询、聚合冲刷、敢调用游戏函数** | **语义精确的 hook 逐条直发 + 无损只读轮询，绝不调用游戏函数** |

## 二、DLL 构成差异（用户指定重点）

| 构件 | 新版 | 老版 | 说明 |
|---|---|---|---|
| 入口/线程 | `dfovib.c`（667 行） | `dfovib_old.c`（483 行） | 老版从 1.5 骨架裁剪：去掉 ini/映射/自动拉起 exe，加上老版轮询与聚合 |
| hook 引擎 | `hooks.c`（1114 行） | `hooks_old.c`（1111 行） | 结构体/stub/E9 改写/VirtualProtect 流程同构；两处分叉见下 |
| 汇编 stub | `hooks_asm.s`（280 行，13 个） | `hooks_old_asm.s`（355 行，13 个） | 老版 stub 更多注释、含返回地址取参等 |
| 协议头 | `common/vib_protocol.h`（223 行，**两版逐字节相同**） | 同一份 + `vib_protocol_old.h`（188 行扩展） | md5 见 `05_DLL构成与源码剖析.md` |
| 配置读取 | `common/ini_util.*` + `common/toml.*`（读 DfoVibration.ini） | 复用同一份（实际未启用，老版零 ini） | 老版 worker 里 `g_iniPath` 从未赋值，ini 读取恒不执行 |
| 注入/代理 | 无（靠游戏官方机制） | `loader_main.c` + `inject_x86.c` + `version_proxy.c` + `dinput8_proxy.c` | 老版专属 |
| 调试工具 | `memtest.c`~`memtest5.c` + `tests/` | 同族（复用 1.5 方法论） | 内存基址验证工具，非成品 |

### hook 引擎两处分叉（40 号报告第二节）
1. **rel32 修位**：老版 v13.16 有 E8/E9 相对指令修位逻辑（0x790D93 卡死换来的）；新版没有——其锚点全是普通指令。
2. **完整性自检**：新版有 60s 首字节 0xE9 自检 + `apiVersion[7]` 上报；老版仅 tick 打 `hooks_active`，v13.39 才补上 60s 自检。
3. 装载数：新版 7 表 hook + 6 个单独 install = 13 点；老版 13 槽装 12（idx11 暴击 0x790D93 永久弃用）。

## 三、事件采集逐通道对比（40 号报告第三节，按 V3 现状更新）

| 通道 | 新版（90US） | 老版（ACT1, v13.39） |
|---|---|---|
| **命中** | 双轨：① 飘字容器轮询（collector 6ms 读 `MEM_G_DAMAGE_FONT` → 容器 → 最新节点 16 字节快照变化 → VEV_ATTACK，80ms 节流）；② 飘字 hook `sub_E010E0` 按 a6 标志计数 → 12ms 批量冲刷。behavior hook 对玩家攻击不触发（仅怪物 AI） | **stub8 飘字咽喉单源**（`sub_470ED0`）逐条直发，10ms 去抖；stub2（评分累加）/stub6（扣血结算）已空转退出 |
| **受击** | 无专门源：靠飘字 `a6&0x02` 计数冲刷 | 双源：`B5ED28` 计数器轮询（主）+ 受击字 + HP 沿佐证 |
| **暴击/特殊** | TextOutW 文字分类（破招/背击有独立 VEV_BREAK/BACK）+ UI 字段轮询（暂缓，恒 0） | stub8 a5 `0x10\|0x01` → 0x10（用户实测确认）+ 暴击数字对象探针（LOG_ONLY） |
| **DOT** | 飘字 0x20 计数冲刷 | 跳字驱动（stub8 红字→0x20 逐条）+ 怪物侧改道 0x04（v13.29）+ stub10 CC 保持式 0x60 |
| **CC/被控** | 无 | ActiveStatus 类型字段（stub10 集 {1,3,7,8}）+ `[ccst]` 探针 |
| **评分** | **纯轮询零 hook**：直接调用游戏函数 `sub_1DD2100`/`sub_1DD4D60` 读等级（变化才发）；评分点=`+3084` 明文累加器增量；破甲/凌空=槽评分增量（调 `sub_1DD3900`）；另加 TextOutW IAT hook 拦 GDI 文字分类（实测零调用，遗留） | hook 播报层 stub1（a2=6/7→VEV_KILLPOINT）+ stub0 状态串（结算演出）；**从不调用游戏函数**（TerSafe 风险） |
| **死亡** | hook `sub_F20BF0`（HP≤0 确认后，排除玩家）+ 轮询击杀计数 `n2500+0x59CC` | hook 通知 38（`0x4217CE`，服务端确认）；B6F608 轮询已证伪停用 |
| **移动** | 轮询明文坐标 + **移速加密解码调制强度 5-100** | 轮询 float 坐标（双源 B75A14/B75A18），强度固定 40 |
| **震屏** | 4 个 hook + 相机字段轮询——**全部搁置不发送**（实测难触发）；仅击杀/死亡特写 VEV_CRIT_SHAKE 实发（按返回地址分类） | stub12 汇聚点（`sub_4E49E0`）→ VEV_KILL 实发（52 次实测） |
| **回复** | 飘字 0x08（玩家状态变化） | stub8 a5 0x04 → 0x08（用户指定通道） |
| **加密读** | `DecodeAdr` 二级查表 XOR（表 `0x42D43E0`）+ `nkpi_key_unwrap` 字符串解密 | **加密双表**（`CFD458`/`CFD45C` 运行时随机密钥 + `sub_402030`）——两版加密体系不同 |
| **结算演出** | 状态串 hook | 同（`sub_433890` 过滤状态串） |

### 事件发送节奏（对宿主手感影响最大的差异）
| | 新版 | 老版 |
|---|---|---|
| hook 回调成本 | 只做原子计数（纳秒级） | 直接组装事件入环（微秒级） |
| 发送节奏 | collector 12ms 批量冲刷：每类一条 `count=N` | 逐条直发 `count=1` + 分级去抖 40/120/200ms + FONT 六子槽 |
| 宿主侧效果 | combo_hits 一次 +N；同类多事件合并为一次注入 | 每事件独立走宿主注入窗 |

⚠ 老版 v13.27 曾照抄新版"计数器+批量冲刷"，实测被用户回退（"仍不适合"）——冲刷改变事件节奏与 count 语义，宿主手感不连续。v13.28 恢复逐条直发；v13.39 的聚合冲刷是折中（计数但**逐条拆发**）。**教训：新版架构可借鉴"源的选择"，不可盲目照抄"发送节奏"。**

## 四、各自独有的资产

**老版特有**：加密 HP/MP 读（hp-probe）、`B5ED28` 受击计数器、ActiveStatus 状态机与 CC 保持震、CNFrenzy 指纹、暴击数字对象探针、FONT 去抖子槽体系、发送统计 tick、rel32 修位保护、Loader/代理 DLL 注入体系。

**新版特有**：ini 热配置与 enabled 开关、autostart 面板、日志轮转、hook 自检、TextOutW IAT hook、**直接调用游戏函数**范式（rank_poll/槽评分——老版因 TerSafe 风险从不调用，此范式对老版**不推荐**）、容器轮询命中、VEV_DODGE/ARMOR_BREAK/AERIAL 等细分事件、平方根强度放大（shake_amplify）、移速调制移动强度。

## 五、宿主演进与双路线（V3 现状）

同一套宿主服务两端，协议不变即复用；差异由 **V3 的 S1/S4+ 双震动路线**承载：

| | S4+（新方案，默认，服务 90US） | S1（老方案，服务 ACT1） |
|---|---|---|
| 量纲 | 饱和满幅脉冲（min(1.0) 封顶） | 线性量纲 + FONT /100 归一 |
| 衰减 | 快衰减 | 保留长衰减 |
| 死区 | 28% 迟滞死区真静音 | 20% 抬底永不落地 + 重映射前置 + 死区只杀真零 |
| 注入窗 | 全局 40ms 窗 | 分通道窗 `last_font_ch[4]`，IVL ≤ 20ms |
| 输出合成 | 独占（评分/移动分支优先） | 合成式 max（评分/移动/战斗三分量共存，v13.37 移植） |
| 群怪治理 | 振幅天然封顶 | 命中限频 hitcap（6 次/秒）+ 群怪聚合 merge_keep/cap/hold + 脉冲落地 tail_land_pct |
| 特殊通道 | 0x04=装备特效 | 0x04=**怪物异常反馈**（独立强度，默认 1%） |
| 事件计数口径 | 全量计数 | 只计真实注入且排除 VEV_MOVE 洪流 |
| 预设 | 通用 6+ 套 | 额外「ACT1 特供」预设（命中 70/出血 10/评分低/死亡 45/全局 90×75 限幅） |

共同点：60 参数槽、`item_lr[26]`/`rank_lr[30]`、效果模式、连击、密度自适应、职业算法 algo_id、移动走路质感——**两路线共用同一引擎，只是 gate 不同**。新方案路径逐字节不变是回归红线。

## 六、选型建议（若要为又一个新客户端适配）

| 若目标客户端… | 建议 |
|---|---|
| 有 `us_extend_dll` 类官方插件机制 | 走新版路线：复用 `dfovib.c/hooks.c` 骨架，只需重定位地址与 ini 参数 |
| 无任何挂载机制、带壳/反作弊 | 走老版路线：复用 `dfovib_old.c/hooks_old.c` + Loader/代理/宿主内置注入；**坚持纯只读、不调用游戏函数** |
| 只想快速验证 | 先按 `07_逆向方法论与地址速查.md` 的换版本清单重定位 P0/P1/P2，再决定采集哲学 |

**可直接复用、无需重找**：hook 引擎与汇编 stub 框架、6ms 轮询框架、共享内存协议（`vib_protocol.h`）、宿主全套（引擎/参数/预设/UI）、加密读法公式结构与"找游戏自身读路径"验证法。
**必须重新定位**：所有游戏内地址、函数锚点、字段偏移、加密表/密钥全局变量、hook 入口字节。
