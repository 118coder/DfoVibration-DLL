- **[auto_inject.rs:49] 注入的 DLL 文件名是 `DfoVibration_OLD.dll`（不是文档写的 `DfoVibration.dll`）。** 其余步骤：1.5s 轮询（L50）、`LAST_INJECTED_PID` 记忆防重复注入（L67-78）、`EnumProcessModulesEx(LIST_MODULES_32BIT)` 找目标 32 位 kernel32 基址（L181-218）、手工读 PE 导出表解析 `LoadLibraryA`（L296-360）、`VirtualAllocEx`+`WriteProcessMemory` 写路径、`CreateRemoteThread` 后 `WaitForSingleObject(10s)`（L254-275）、DLL 定位宿主目录优先→DNF.exe 目录（L122-142）。建议补进 02 §3③。

- **[safety.rs:24-67] 紧急保险热键 Ctrl+Alt+Shift+A → `ExitProcess(0)`。** 独立线程 + `RegisterHotKey`（MOD_NOREPEAT），不受软件自身 SendInput 触发；注册失败静默跳过。文档 02 §8.3 讲 v1.6 稳定性时完全没提。建议补进 02 §8.3 或 08 §7。

- **[util.rs:180-200 + main.rs:34-44] 线程看护与 panic 策略。** `spawn_supervised` 捕获线程 panic 后自动重启，`MAX_RESTARTS=10`，超过则记 `crash_log` 并放弃重启但**进程保持存活**；全局 panic hook 写 `SorahkDFO_crash.log` 后 unwind。文档 02 §8.3 只说"最多 10 次"，没提 crash.log 文件名与"放弃重启但保活"。建议补进 02 §8.3。

- **[vibration.rs:2127-2273] 共享内存消费的不可信输入校验。** 只有 `magic==0x564F4656 && version==2 && process_alive(game_pid)` 才连接；环合法性用 `head.wrapping_sub(tail) <= capacity`（不能用 head<=capacity 判，玩一会 head 超容量后恒判非法导致震动中断）；非法时 `tail=head` 丢弃积压并在 ok→invalid 跳变时记一条 `VIB_RING_INVALID`；断开时整引擎 `VibEngine::new()` 重置（旧实现只清 left/right 会残留 deadline 卡死）。**[vibration.rs:2049] 宿主声明了 `api_version[7]/flags/seq/last_tick` 但从不读取**——文档 02 §4 说 apiVersion 供宿主校验，实际 V3 宿主不校验。建议补/修正 02 §4、§7。

- **[vibration.rs:2232-2243] S1 计数口径**：只有 `engine.last_injected && etype != VEV_MOVE` 才计入 `vibration_events_received`（移动洪流 6ms 续期不计），S4 全量计数。建议补进 06 §6。

### G. 输出链细节

- **[vibration.rs:1929-1943] `send_vibration` 遍历槽位 0..4，输出到第一个 `XInputGetState` 成功的槽位。** 旧实现硬编码 0 号槽导致非 0 槽手柄收不到震动。文档 02 §8.2 写的是 `XInputSetState(0, {...})`。建议修正。

- **[vibration.rs:1549-1555, 1374-1382] 走位能量 move_charge**：移动中按 `p[21]`%/秒积累（上限 1.0），停手后按 4s 线性流失；停手窗口 `p[39]` 内的下一次攻击 `× (1 + charge × p[22]/100)`。文档完全没提这个 v22 机制。建议补进 06 §5.4。

- **[vibration.rs:963-978, 1561-1572] 唤醒/里程碑/连击中断脉冲**：进入战斗首击（或 >5s 无事件）发 `p[56]` 唤醒脉冲；跨 50/100/200/400 发 `p[57]` 里程碑脉冲；连击超 `p[49]` 门槛且 `p[45]` 窗口内无连击发 `p[58]` 收尾脉冲。文档未提。建议补进 06 §5.4。
