# 02 新版本技术路线（90US 挂载式）

> 适用对象：**90US 新版 DNF 客户端**（32 位进程、无壳、主代码段 R/W/X 可直接改写、游戏自带 `us_extend_dll\` 插件加载机制）。
> 主角：采集 DLL `DfoVibration.dll` + 宿主 `SorahkDFO.exe` / `DfoVibration-V3`。
> 素材来源：`DfoVibration_OLD/docs/阶段报告/04_1.5DLL源码剖析.md`（带行号的逐文件剖析）、`05_1.5宿主软件架构.md`、`03_1.5事件采集方法论.md`、`1.5版/开发文档/00_项目总览与无损续接指南.md`、V3 `HANDOFF.md` 与 `震动系统开发规范_v20.md`。所有地址与数值均照抄原文。

## 一、定位与一句话结论

**DLL 只做只读采集（hook + 内存轮询 + 调用游戏只读函数），把战斗事件写进共享内存环形队列；宿主 SorahkDFO 读共享内存、跑震动算法、用 XInput 驱动马达。游戏本体一个字节不改。**

- 挂载方式：**官方插件机制**（放 DLL 进 `us_extend_dll\` 即被加载），不需要注入器。
- 参数归宿：**DLL 自身 `DfoVibration.ini`（极简）+ 宿主 GUI**；与老版不同，新版 DLL 侧有 enabled/各 gain 等 ini 参数（500ms 热加载，enabled 动态装卸 hook）。
- 采集哲学（与老版的核心差异）：**「轻 hook、重轮询、聚合冲刷、敢调用游戏函数」**——hook 回调只做原子计数（纳秒级），由 collector 12ms 批量冲刷；评分等级等直接调用游戏纯函数读取，从不 hook UI 热路径。

**目标客户端画像**（`DFO_战斗系统逆向分析.md`）：`DFO.exe` 87,171,072 B；151,357 函数（1,187 已命名）；节名加密（`___`/`.naim`/`yagwkjhl`）但**非壳**、代码可正常反编译；反作弊 = XignCode 残留 + 官方自研 `usdof_client_guard.dll`（仅模块固定+监控，**不拦截扩展 DLL**）；导入 Lua 5.1.5(lua_tinker)、protobuf(C2S/S1/S0)、D3D9+D3DX9_43、DirectInput8（**游戏本身不导入 XInput**）、FMOD、Awesomium、ZeroMQ、steam_api。战斗主干 = Behavior 系统（每个行为对象挂 Lua 状态机，C++ 层把事件分发给 Lua，Lua 经 AIBridge 反查对象信息）。

## 二、总体架构

```
游戏进程 DFO.exe (90US, x86)
  us_extend_dll\DfoVibration.dll   ← 官方启动器扫描目录自动加载（导出 DfoVibrationLoaded）
    ├─ 7 个行为 hook（g_hookTargets，OnAttack/OnDamage/...）
    ├─ 6 个功能 hook（伤害飘字咽喉 / 震屏×3~4 / 怪物死亡 / 直接震屏）
    ├─ 汇编 stub 0-12：保存现场 → 调 C 分发 → 跳 trampoline
    ├─ 轮询（collector 线程 6ms）：评分等级/评分点/击杀/移动/闪避/相机震屏/飘字容器
    └─ 写共享内存 Local\DfoVibrationShm（VibShm 头 + 256KB 环形缓冲，CAS 写）
          │
宿主 SorahkDFO.exe / DfoVibration-V3（Rust + egui，独立进程）
    vibration 线程 15ms 轮询共享内存 → VibEngine（60 参数槽合成）→ XInputSetState
    GUI：连发映射 / 通用型震动设定 / 全职业预设（V3 另加手柄可视化页/白名单页/极简模式）
```

进程隔离的意义：DLL 内只做采集，算法/UI 崩溃不影响游戏；删除 DLL 即完全还原。

## 三、DLL 如何进入游戏（三条途径）

| # | 途径 | 机制 | 现状 |
|---|---|---|---|
| ① | **官方 us_extend_dll 自动加载** | 游戏启动器扫描 `游戏目录\us_extend_dll\*.dll` 并调用导出 `DfoVibrationLoaded()`（幂等：CAS 保证只起一次线程）。安装 = 把 `DfoVibration.dll` + `DfoVibration.ini` 放进该目录 | 1.5 版主途径 |
| ② | **外部注入（契约预留）** | `LoadLibrary` 加载后调用导出 `VibPluginLoaded()`（与 ① 同义）；`VibPluginDeinit()` 卸载 | DLL 一直预留（`tests\test_load.c` 演示） |
| ③ | **V3 宿主内置 auto_inject** | 宿主内置线程 1.5s 轮询、**x64→x86 跨位注入**（`EnumProcessModulesEx(LIST_MODULES_32BIT)` 找目标 32 位 kernel32 → 手工读 PE 导出表解析 `LoadLibraryA` → `VirtualAllocEx`+`WriteProcessMemory` 写路径 → `CreateRemoteThread` 后 `WaitForSingleObject(10s)`）；`LAST_INJECTED_PID` 记忆防重复注入；DLL 定位 = 宿主目录优先、其次 DNF.exe 所在目录；**无 DLL 则不注入**（普通连发玩家零影响）。⚠ 注入的是 **`DfoVibration_OLD.dll`**（老版本名，不借代理名） | V3 新增（HANDOFF 第 21 条）；S4+ 路线状态行显示「S4 震动模块自动注入 · 已启用」 |

要点：DLL 自身 `DllMain` 在 `DLL_PROCESS_ATTACH` 即自建线程，因此**无论走哪条途径，只要进了进程就开始工作**；官方启动器调用导出函数只是兜底幂等。

**us_extend_dll 官方协议细节**（`DFO_战斗系统逆向分析.md`）：目录 `游戏目录\us_extend_dll\*.dll`；DLL 导出 `XxxLoaded`（先例 `BgmRestorationLoaded`/`AudioCleanupVLoaded`/`UsdofSoundFixLoaded`）；启动器（含 `"usdof_func_extend"` 字符串）在 DFO.exe 启动时加载并调用导出；配置 = 同目录同名 `.ini`（`[Main] Enabled=1 Interval=50 Debug=0` 风格）、日志同名 `.log`；运行时只依赖 KERNEL32 + UCRT，无第三方依赖；官方守护不拦此渠道。

**内存模式（方案 B，零注入兜底）**：`OpenProcess` + `ReadProcessMemory` 10ms 轮询 `dword_415C5D8`（行为管理器单例）→ 玩家对象；HP/位置经 `vtable+1016/1024/1028`、xPos/yPos 读取。精度低于 DLL 模式，但完全无注入。

## 四、DLL 生命周期与线程模型（`dfovib.c`）

```
DllMain(PROCESS_ATTACH):
  g_hDllMod = hDll; DisableThreadLibraryCalls(hDll)
  CAS(g_workerStarted, 1←0) 只启动一次 → CreateThread(worker_thread) + CreateThread(collector_thread)
DllMain(PROCESS_DETACH):
  g_running=0 → 等 worker/collector ≤1500ms → hooks_uninstall + textout_hook_uninstall + shm_close
```

**worker_thread（主控，每 500ms）**
1. 先 `Sleep(1000)` 避开 DllMain loader lock 窗口，之后才允许调可能加载 DLL 的 API（ShellExecuteA / Toolhelp32）。
2. 解析自身路径：必须用 `GetModuleFileNameA(g_hDllMod,…)`（传 NULL 会得到 EXE 路径）；手动映射注入时 DllMain 可能不触发，兜底用 psapi 枚举模块找文件名含 "DfoVibration" 的模块。
3. **日志/配置文件由 DLL 文件名派生**（`DfoVibration-V.dll → DfoVibration-V.ini / .log`），支持多版本共存；日志超 2MB 自动轮转为 `.old`。
4. 每轮读 ini → 检测 `enabled` 变化：启用时顺序 = `shm_open()` → `hooks_install(g_hookTargets, 7)` → 追加 6 个功能 hook → `textout_hook_install()` → 把 hook 目标地址写 `g_shm->apiVersion[7]`（⚠ 源码核查更正：DLL 会写，但 **V3 宿主实际不读取 api_version**，只校验 magic/version/game_pid）；禁用时反向卸载。
5. 每 60s **hook 完整性自检**：检查 hook 目标首字节是否仍为 `0xE9`，否则告警 `hook overwritten - runtime self-protection?`。
6. 自动拉起控制面板：`autostart_exe()` 用 Toolhelp32 查重后 `ShellExecuteA` 启动同目录/上级目录的面板（开关 ini `AutoStartExe`）。

**collector_thread（采集，每 6ms）**：跑全部 `poll_*` 轮询；聚合冲刷按 **12ms 节拍**（把 hook 计数器的增量批量发事件）。

## 五、hook 引擎原理（`hooks.c` / `hooks_asm.s`）

新版无壳，`DFO.exe` 主段本身 R/W/X，**不需要 VirtualProtect**（老版必须查页属性）。

1. **Patch 模板**：目标函数前 `hookLen` 字节改写为 `E9 rel32` + 剩余字节 `NOP`；`rel32 = stubAddr - target - 5`。
2. **变长 hook（必修）**：`calc_hook_len()` 从 5 字节起，用**手写精简反汇编器 `insn_len()`** 逐条累加指令长度，直到 ≥5 且落在完整指令边界——防止截断指令导致「只第一次触发 + 概率闪退」。
3. **安全检查**：`first_insn_safe()` 拒绝以 `E9/E8/EB/C3/C2` 开头的目标；`target_writable()` 要求页已提交且可执行。
4. **Trampoline**：一次 `VirtualAlloc` 出 `VIB_MAX_HOOKS*32` 的 RWX 页，每槽 = 原指令 memcpy + `E9` 回跳原函数剩余部分；地址存入 C 全局 `vib_tramp_N`。
5. **汇编 stub**（13 个）：`pushfd`(4) + `pushad`(32) = 36 字节现场 → `push <事件类型立即数>` → 按调用约定取参（返回地址在 `[esp+36]`、a2 在 `[esp+44]`、a3 在 `[esp+48]`）→ `call vib_dispatch_*` → `popad/popfd` → `jmp _vib_tramp_N`。
   - stub7（伤害飘字，参数多）= `vib_dispatch_common_hit(this,a2,a3,a6,type)` 5 参。
   - stub8（技能震屏）= `vib_dispatch_skillhit(this,strength,time,retaddr,type)`，**用返回地址分类调用者**（击杀特写 vs 相机内部）。
   - 其余为 `vib_dispatch_common/common/shake/readshake/targetdie/directshake`。
   - ⚠ 事件类型是**硬编码立即数**，与 stub 索引无关（stub5 是 TargetDie 但 push 的是 `2`）。
6. **钩子链管理**：`HookCtx{target, patchRel, original[16], hookLen, stub, trampVar, installed}` 数组，追加式安装（7 行为 hook + 6 功能 hook 分两批）；卸载时 memcpy 还原原字节。

## 六、事件采集的四种手段

### 6.1 行为 hook（7 基址，`g_hookTargets`）
`0x007885A0` OnAttack / `0x00788480` OnDamage / `0x00788730` OnStartBattle / `0x00788700` OnResetCombo / `0x00788760` OnActionEnd / `0x007884C0` OnTargetDie / `0x02AFADB0` OnShakeInput。
强度折算在 `vib_dispatch_common`：VEV_DAMAGE 取伤害对象 `vtable+808` → `+68` 伤害值（>100000 截断）；其余默认值。
⚠ **2026-08-15 实测：behavior hook 对玩家攻击不触发（仅怪物 AI/技能对象），玩家侧改轮询/飘字咽喉。**

### 6.2 伤害飘字咽喉 hook（核心命中源）
`sub_E010E0`（0x00E010E0）= 飘字对象初始化唯一入口（`sub_E03210` 创建飘字、30 个调用者）。hook 它拿 **a6 类型标志**：

| a6 位 | 值 | 语义 |
|---|---|---|
| bit0 | 0x01 | 玩家命中 |
| bit1 | 0x02 | 玩家受击 |
| bit2 | 0x04 | 装备特效 |
| bit3 | 0x08 | 玩家状态变化（无敌/霸体/HP 回复） |
| bit4 | 0x10 | 特殊攻击（暴击/破招/背击共用） |
| bit5 | 0x20 | 持续伤害 DOT |

**性能关键**：hook 回调只 `InterlockedIncrement` 对应计数器（纳秒级）；collector 每 12ms `InterlockedExchange` 取增量，批量发 `VEV_FONT(strength=类型位, count=次数)`。优先级取强度：`0x20 > 0x10 > 0x08 > 0x04 > 0x01 > 0x02`。
另有**飘字容器轮询**：`MEM_G_DAMAGE_FONT = 0x0415D2B4` → +8 容器 → +4 链表头节点；节点变化 +80ms 去抖 → VEV_ATTACK+VEV_DAMAGE；节点消失 >500ms → VEV_ACTION_END。

### 6.3 纯内存轮询 + 直调游戏只读函数（零 hook）
| 通道 | 实现 | 关键坑 |
|---|---|---|
| 评分等级 | `rank_poll`：读 `dword_4187B54` → 直调 `sub_1DD4D60`(取伤害) + `sub_1DD2100`(等级 0~8)，变化才发 VEV_RANKING | 过滤条件必须是 `lvl > 8` 才丢（`lvl < 2` 会丢 SS/SSS）；满幅用时间戳（300ms）而非单帧 |
| 评分点 | 读评分对象 `+3084` 明文累加器增量 → VEV_KILLPOINT | 读后游戏会清零，只发增量防刷屏 |
| 破甲/凌空 | `sub_1DD3900(score, slot_bits(4/5 或 10/14), idx)` 槽值增量 | **slot 参数是整数位模式（IDA COERCE_FLOAT）**，传真实 float 触发游戏断言崩溃 |
| 极限闪避 | `(*n2500+856)(n2500)` 0→1 上升沿 → VEV_DODGE | 开局延迟 3s 防假阳性 |
| 击杀/释放技能 | `n2500(0x4294CE8)+0x59CC` 计数增量 → VEV_KILL | 实测语义是「技能释放计数」，非纯击杀 |
| 移动 | `n964(0x418A458)+4/+8` float 坐标，位移 ≥1px 判定；强度 = `vib_decode(n2500+0x9A8)` 移速解密调制 5-100 | 300ms 无位移发 VEV_MOVE(0) |
| 相机震屏 | 相机对象 `0x4158A38+1952` 强度上升沿 | 4 个 hook + 轮询均已搁置不发送（用户实测难触发） |

### 6.4 TextOutW IAT hook（遗留，实测无效）
IAT 槽 `0x0571C474`，改写指针 → 复制文本 ≤95 wchar → `classify_font_text()` 关键词分类（SSS/CRIT/BREAK/BACK…）→ 命中则发事件 → 转发原函数。
⚠ **1.5 研究结论：游戏 UI 走内部位图字体（NPK），TextOutW 实测零调用，此路径已证伪**；代码保留属遗留。

## 七、事件协议（DLL ↔ 宿主 ABI 契约）

共享内存 `Local\DfoVibrationShm`，magic `0x564F4656`，version 2，256KB 环形缓冲；事件 `VibEvent{type,strength,tick,reserved}` 16 字节；head 由 CAS 推进、满则丢弃（回绕安全用无符号差 `(DWORD)(head-tail)>=capacity`）。

⚠ **head/tail 是"累计字节偏移"不是环内索引**（`稳定性修复记录_v1.6.md` 问题 10）：DLL 每写一事件 `head+=16`、宿主每读一事件 `tail+=16`，会持续超过 `capacity=262144`，靠 `% capacity` 取环内位置。v1.6 曾把校验误写成 `head<=capacity && tail<=capacity` → 累计超 262144 后 `ring_ok` 恒假 → **每轮事件被丢弃、玩一会后震动中断而映射正常**；修复 = `head.wrapping_sub(tail) <= capacity` + 异常自愈 `tail=head`（非法时丢弃积压并记一条 `VIB_RING_INVALID`，断开时整引擎 `VibEngine::new()` 重置）。宿主只校验 `magic/version/game_pid`，**不读 `api_version[7]`**（该字段是 DLL 单方面上报的遗留）。

`VEV_*` 事件枚举（0-25）：ATTACK=0 / DAMAGE=1 / TARGET_DIE=2 / RESET_COMBO=3 / START_BATTLE=4 / ACTION_END=5 / SHAKE_INPUT=6 / HP_LOST=7 / RATING=8 / COMBO=9 / **FONT=10（strength=a6）** / RANKING=11 / KILLPOINT=12 / DODGE=13 / CRIT=14 / BREAK=15 / BACK=16 / FINAL_KILL=17 / AERIAL=18 / ARMOR_BREAK=19 / BUFF_STACK=20 / KILL=21 / SHAKE_SCREEN=22 / MOVE=23 / SKILL_HIT=24 / CRIT_SHAKE=25。
铁律：**DLL(`vib_protocol.h`) 与 Rust(`vibration.rs` 常量) 必须同步；枚举只加尾部，不改已有值。**

## 八、宿主 SorahkDFO / V3

### 8.1 模块与职责
`main.rs` 启动编排（配置→AppState→键盘/鼠标钩子线程→InputManager→振动引擎线程→托盘→GUI）；`config.rs` TOML 读写；`state.rs` 原子状态中枢；`keyboard.rs/mouse.rs` 全局钩子 + `WorkerPool` + SendInput；`xinput.rs` XInput 5ms 轮询；`rawinput.rs` HID/RawInput；`input_ownership.rs` 设备归属仲裁（XInput 优先）；**`vibration.rs` 震动引擎（共享内存消费 + 60 参数合成 + XInputSetState）**；`job_presets\` 14 基础职业文件；`gui\` egui 界面。

### 8.2 震动管线
```
vibration 线程 15ms: OpenFileMappingW("Local\\DfoVibrationShm") → 校验 magic → 校验 game_pid 存活
  → 从 tail 消费到 head：engine.push_event(ev)   // 按事件类型取参数槽强度/L-R 权重
  → engine.tick()：衰减/保持/节拍推进 → engine.finalize(params)：总闸×上限×连击×曲线×密度
  → 输出平滑 → 随机增益 → 马达增益 → **遍历槽位 0..4** 调 XInputSetState（输出到第一个 XInputGetState 成功的槽位；旧实现硬编码 0 号槽会让非 0 槽手柄收不到）
```
- 事件→通道：FONT 六类各取 `params` 对应槽 + `item_lr` 权重；评分等级 `rank_strength(level)`；细分事件 `rank_type_strength × rank_type_gain[15]`。
- 效果模式：decay（瞬间脉冲）/ hold（持续保持）/ rhythm（节拍方波）；V3 另加 mode3（DOT 衰减脉冲）/mode4（怪物 DOT 脉冲）。
- 手感算法：输出曲线 `powf`、死区+迟滞、动态范围重映射、马达分工（Xbox360 风格）、移动正弦走路质感（步频 380ms/相位交替/平滑/低阈值抑制）、连击密度自适应、节流窗口、评分动态衰减（类鬼泣）、**职业专属算法 algo_id**。⚠ 更正：algo_id 实际取值 **1~57（每个转职一个）**，按 **13 组行为 A-M** 分派（A 连击步长/B 蓄势重击/C 周期脉冲/D 特殊追加/E 窗口爆发/F 受击保护/G 标记增强/H 叠层/I 暴走/J 连段完成/K 绝对频率/L 交替连击/M 连点组）；文档旧写"1-15"源自 `job_presets/mod.rs` 的过时注释。算法族名（连携脉冲/收刀爆发/刚拳蓄势/弹幕连点/空袭轰炸/蓄气爆发/圣光追加/庇护缓冲/暗杀标记/盾牌格挡/战意昂扬/自由连段/交替连击/连点组/绝对频率）见 `08` §5。
- 参数体系：`params[60]`（0-18 基础 / 19-59 高级）、`item_lr[26]`、`rank_lr[30]`、`rank_type_gain[15]`；所有强度 0-100、时长 ms；L/R 权重 -100..+100 补码存 u32。详见 `08_配置文件说明.md`。

### 8.3 V3 相对 1.5/v1.6 的演进
1. **v1.6「绝对稳定化」**（2026-08-30）：线程 panic 只记日志并自动重启（`spawn_supervised`，panic 后 300ms 重启，`MAX_RESTARTS=10`，超过则写 `SorahkDFO_crash.log` 并放弃重启但**进程保持存活**；`panic=abort`→`unwind`）；事件背压自动合并（全局积压计数 ≥512 触发 `drain_and_coalesce`，只保留每键最新按下/松开、**松开必然保留**）；手柄报文/共享内存按不可信输入逐项校验；注入时长/间隔钳位（`input_timeout` [1,2000]ms、`double_tap_gap_ms` [1,500]ms）；系统回调加防护；锁防中毒（7 处 `Mutex/RwLock.unwrap()` 替换为 guard）；退出最多等 3s。**另有独立紧急保险**：`safety.rs` 全局热键 **Ctrl+Alt+Shift+A → ExitProcess(0)**（`RegisterHotKey(MOD_NOREPEAT)`，不受自身 SendInput 触发，注册失败静默跳过）；**注入保险**：每秒注入 >900 单元自动冷却 1 秒（冷却期整体透传，不拦截不注入）；**IME 打字暂停**：`ImmGetCompositionStringW(GCS_COMPSTR)` 检测，v1.6 改 10ms 节流缓存。
