## 三、未定位清单 + 关键负结果（勿重复踩）

### ⚠ 负结果 1：+0x155C 是状态块状态ID，**不是 HP**（本轮回调最重要的一条）

`+0x155C` 槽（505 处引用，密度第一）和 `+0x1828`（276 处）解密后出现在**限时状态 tick** 里：
`sub_7C2F90`: `sub_402060(this+0x155C) == 22` → 状态 22 的累计器（+0x2844）满 1500 时 DOT 结算 + 双表打"变化标记"。
**这是 ACT5 v13.17 踩过的同型雷**（把状态块完整性标记当 HP 表下标）。玩家 HP 槽在 60US 需另行定位（候选思路：找 `add ecx,IMM; jmp sub_402060` 的 GetHP 型 thunk）。

### ⚠ 负结果 2：伤害数字系统换架构，ACT1/ACT5 单咽喉不存在同构形态

60US 数字系统 = **槽位记录池 + 124 字节/项字模表 + 每帧冲刷**：
- 记录字段自密钥加密（`dword_10D3EF8 ^ (值-字段地址)`，与 P0 双表并行的**第二套自密钥**，见 sub_A27360 重置代码）；
- 冲刷器 `sub_A26990(container, mgr, x,y,z)` 遍历记录 → `sub_A265D0(mgr, x=a2, y=a3, ?, a5, **字模索引=a6**, ...)` → `sub_A23E90(...)` 落屏；
- **a6 是字模索引（124 字节表下标），不是标志位**——ACT1 的 cdecl(Src,x,y,z,伤害,标志) 布局在这里**不存在**，stub8/stub13 不能直接套。

## 六J、★v5.1 进战斗即崩事故：rel32 修位差 1 字节（2026-09-24, 证据链到字节）

**现象**：v5.1 装上后玩家进战斗立刻崩退；日志在第一次 `[pb1]` 触发那一行之后戛然而止。

**证据链（四条互相印证，根因无歧义）**：
1. Windows 事件日志 06:53:50 Application Error：
   `DFO_fixed_v3.exe`，**异常代码 `0x4000001f`**，**错误偏移 `0x0009897f`**。
2. `0x4000001f` = `STATUS_WX86_BREAKPOINT` —— WOW64 下 32 位进程执行 **int3(0xCC)** 的报码。
3. `ImageBase 0x400000 + 0x9897F = 0x49897F` = **生成器入口 0x498980 的前一个字节**（函数间 0xCC 填充区）。
4. 日志最后一行 `[pb1] first ret=22623000 …` —— 探针分派**先写日志**，随后 stub → trampoline 重放 `call` 才跳飞，故"最后一行 = 崩溃前最后一次成功动作"完全吻合。

**根因**：v5.1 给探针引擎加了 rel32 修位（为了挂钩生成器**调用点** E8），公式照抄主引擎 `hook_one`：

`call` 指令位于 tramp 块首 `t`，位移基准必须是**下一条指令 = t+5**。旧式 = `orig_target - t - 6` ⇒ 落点 `= orig_target - 1`。实测 `0x8C4128` 处 call（原目标 0x498980）修正后落点 `0x49897F` —— **与崩溃偏移完全一致**。

**为何此前没暴露**：主引擎 `hook_one` 里同一处代码是潜伏雷 —— 已装锚点首字节全是 `0x55`，永远走不到 `E8/E9` 分支；ACT1 的 0x790D93 当年是**直接放弃安装**（改无损轮询）而非验证修位。本次是这段代码第一次真正被执行。

**修复（v5.2, md5 `9050866d243424ab34d8d2e6b437a878`）**：
1. 两处公式统一为 `orig_target - (t + 5)`；
2. 新增**装机回读自校验**：写完位移后从字节回读 `(t+5)+disp`，必须等于原目标，否则**拒装并记日志** —— 这类错误必须在装机时炸出来，而不是等玩家进战斗（同"8 字节签名自检"的思路）；
3. **探针全面回到非相对指令靶点**，彻底不依赖 rel32 能力（见下）。

**★v5.2 靶点（四条全部实测"覆盖段无相对指令"）**：
| 槽 | 地址 | len | 签名 | 作用 |
|---|---|---|---|---|
| 0 | `0x498CBB` | 8 | `8B 4D 1C 8B 55 18 51 52` | 生成器内 **ctor 调用前**：帧指针一次取全 场景/伤害/标志/宿主 |
| 1 | `0x498620` | 10 | `55 8B EC 6A FF 68 7E 69` | 构造器入口（v4 已验证） |
| 2 | `0x498980` | 10 | `55 8B EC 6A FF 68 A5 69` | 生成器入口（v4 已验证） |
| 3 | `0x517040` | 10 | `55 8B EC 83 EC 58 53 56` | 解码器入口（v4 已验证） |

槽 0 是本次的关键设计：挂 `call 0x498620` 之前 8 字节，用寄存器捕获 stub 拿到的 `ebp` 读生成器帧 ——

## 六L、★v5.2 第二次进战斗崩溃：探针桩冲掉 EAX → 构造器 this 变成我们自己的 tramp 页（2026-09-24）

**先说好消息**：这一场探针**采到了完整且自洽的伤害数据**（三条探针交叉验证）：
```
[pd] site#0 call=008C412D flags=00000001 dmg=860 host=08F76000
[pb2] ret=008C412D a=08F76000 000002AA 000001A5 0000008C 0000035C   ← a1=宿主 a5=伤害0x35C=860
[pb1] ret=00498CCA a=0000035C 00000001 1D3A4020 00000000 1CEF4CF8   ← a1=伤害860 a2=标志1
```
三个独立探针给出的伤害值一致（860），调用点=主路径 0x8C412D，标志=0x01。

**然后第二次伤害数字时崩了**（WER）：
```
异常代码 0xc0000005 (访问违例)   出错模块 unknown   错误偏移 0x0fc80048   进程 35120
```
`[pb1]` 记录的构造器 `this`(ecx) = **0x0FC80000** —— 页对齐、且不属于任何模块。

**根因（逐条对得上）**：
1. 钩点 `0x498CBB` 是生成器内的一部分，其后紧跟
   `0x498CC3 mov ecx, eax`，**EAX 里装的是刚分配出来的伤害数字对象**。
2. 而探针桩的收尾是 `mov eax, _vib_probe_tramp_N / jmp eax` —— **把 EAX 冲成了
   我们自己的 trampoline 页地址**（17 处桩全是这个写法）。函数入口处 EAX 不是活值，
   所以 v3/v4 一直没暴露；这是第一次把钩点放进函数内部，于是立刻踩中。
3. 生成器因此把 **tramp 页地址当作 `this`** 交给构造器；构造器往里写了整份对象
   （vtable + 各字段 0x20C 字节）→ **把我们自己的 trampoline 覆盖成了伤害数字对象**。
4. 第 2 个伤害数字到来时跳到已被覆盖的 trampoline → 执行垃圾字节 → AV，
   崩在 `0x0FC80048`（= 那个页 +0x48，正好是相邻探针的 tramp 块位置）✓
   ——日志停在"第 2 次伤害的生成器入口之后、构造器入口之前"也完全吻合。

**修复（v5.3, DLL md5 `477d6297c1c8dd34808b882398445a84`）**：
- **全部 20 处桩尾统一改为不破坏任何寄存器**：
  ```asm
  push dword ptr [_vib_tramp_N]   ; FF 35 imm32 —— 不需要临时寄存器
  ret                             ; C3
  ```
  含 `PROBE_STUB` **宏体**内的那处（宏用参数 `\tramp`，字面符号替换会漏掉 ——
  第一轮只改了 17 处，靠符号级反汇编复核才发现 stub 1/2/3 仍是旧写法）。
  复核方式固化在 `work/60us/p46_stub_tail_check.py`（字节模式 + 符号级反汇编双查）：
  当前 0 处旧式 / 20 处新式 / 桩内无 `jmp eax`。
- **装机时把 tramp 页/桩地址写进日志**：`[probe] N tramp@… stub@… (tramp page @…)`
  ——以后再出"游戏侧指针异常"，可直接与我们自己的页对号（这次就是靠它定位）。
- 规则沉淀（写进 asm 头注释）：**函数内部挂钩点必须假设其后每条指令的寄存器
  依赖都要被满足**；桩与 trampoline 都不得动任何寄存器/标志/栈。
- 装载器尸体日志改为最多记 4 具、各只报一次（先前两只僵尸交替刷屏，掩盖信号）。

**回归**：ACT1/ACT5 两个剖面重新构建通过；60US 四个探针靶点仍为非相对指令、边界整指令。

**这一课**："无害探针"并不无害 —— 往运行中的函数中间塞一条跳转，等于要求跳回来之后
**一切（寄存器/标志/栈）都与没被插过一样**。桩尾那一行虽然只是"跳去 trampoline"，
却动了 EAX，而这正是下一条指令要用的东西。**根本对策是把"不破坏现场"变成
汇编层面的结构性保证（push 内存 + ret），而不是靠人逐个核对。**
