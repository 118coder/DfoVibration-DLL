### 二、定位套路（可复用）

1. **字符串/NPK 路径线索 → XrefsTo 回溯**：`sprite/interface/result.img`、`Combo.img`、`R_STAGE_FINALE`、`%sNumber.img` 等明文串 → 交叉引用 → 所在函数 → 顺藤摸瓜。音效不走文件路径（`finale1/2.wav` 不在 exe，走 `SoundPacks/audio.xml`+`String.lst` 标签映射）。
2. **xref 数量本身是语义信号**：2274 处引用 = 全局热指针/缓存句柄；26 处 = 专属对象（评分对象）；849 refs = 玩家对象。先看数量分布再定性。
3. **先零 hook 轮询**：能靠明文计数/位置字段增量解决就不 hook（击杀计数、移动坐标、评分等级全部轮询）。
4. **选"唯一汇聚点/唯一收口"**：`sub_433890`（715 调用点统一事件发送器）、`sub_4E49E0`（68 xref 全震屏唯一出口）、`sub_1E268F0`（仅 2 调用者 [shake screen] 唯一收口）。先穷举调用者分类（个数、返回地址、参数常量）再下钩。
5. **按返回地址分类调用者**：同一汇聚点被多类调用者共用时，hook 内取返回地址区分（新版 stub8、老版 v13.33 ret 探针）。
6. **排除法验证**：先试高层回调，实测不触发就往底层换（OnTargetDie → `sub_1C58AC0`）。
7. **变长 hook 是必修**：`insn_len()`/`calc_hook_len()` 指令边界对齐 + trampoline + `original[16]` + NOP 填充；"只第一次触发 + 概率闪退" = 指令截断的典型症状。
8. **黄金标准 = 找游戏自身读该字段的代码路径**：HP 槽 `+0x1168` 的铁证是游戏自身 GetHP thunk `0x652A20: add ecx,1168h; jmp sub_402030`。静态定案再漂亮不如一条直证。
9. **字段语义必须先探针实测标定再进判定集**：条件码 `+0x42C` 被静态推断成"被抓"，实测每刀攻击（含未命中）都触发 → 整条 CC 路线翻车（v13.21 事故）。语义不明的通道先加 5s 节流探针观察。
10. **同一标志位在不同调用点语义不同**：`sub_470ED0` 的 a5 在 `sub_4748D0` 与 DOT 三兄弟含义不同（教训 19）；方向性结论（编译器 setnz+dec+and 惯用法）要两方独立验证。
11. **单观测点歧义时找写入者链的分歧点**：HP 掉血分不清受击/血之狂暴 → 用 `player+0x2A14`（CNFrenzy 指针）做判据，而不是在 HP 值本身找模式。
12. **先判断"该判定是否在客户端计算"**：背击（朝向）/破招（受击状态）大概率服务器判定，客户端静态穷举成本过高 → 走回包解析/结算 UI（v17-19 全记录是范本）。
13. **探针先行 + 判定器闭环**：`LOG_ONLY` 探针（`[f]`/`[s6]`/ret/`[town]`/`[mvB]`）+ `work/analyze_hit.py`（每次实测后一键输出 a5 谱系/ret 归因/间隔直方图/吞段模拟/tick 对照）——**模拟与实际吻合才算闭环**（如 10ms 窗模拟发出 217 = tick 实际 a=217）。

### 三、验证与交付纪律

1. **用户实测 > 一切代码分析**（神枪手盲区、霸体规律、走位不震三次都是用户观察修正了分析结论）。
2. **「已验证」必须能指出哪次实测、哪条日志作证**；指不出的降级"待验证"。
3. 每版 DLL 备份进 `release_backup/`，回退点随时可用。
4. **构建后字节级验证**关键日志串/静态变量真的在二进制里（LLVM -O2 常量折叠曾把探针整段判成死代码）。
5. **分职业（近战/远程）+ 分场景（走位/站桩、城镇/副本）验收**。
6. 部署前查目标进程；绝不删除用户正在运行的文件（改用新文件名+报告切换）。
7. **一次一事**：patch → 构建 → 字节验证 → 部署，四步不拆开（曾因拆开部署了不含修复的版本）。
8. 跨进程日志对齐先校时钟域（DLL GetTickCount vs 宿主毫秒戳，曾因时钟域不同白跑一轮）。
9. **只读读法纪律（报告 27 定稿）**：安全读用 `VirtualQuery` 页预检（不触页、零异常、TerSafe 无感）+ `__try/__except(EXCEPTION_ACCESS_VIOLATION)` 兜底；**弃用 `IsBadReadPtr`**（SEH 滥用有被 VEH 观测风险 / 破坏 guard-page 堆状态 / TOCTOU 无解）。
10. **AOB 必须全变体扫描 + 语义反编译**：不能照抄旧客户端/1.5 的特征码——老版全库扫描证明 `89 B3 24 05 00 00` 零命中，`89 83 24 05 00 00`@0x476850 写的是 GetTickCount 时间戳（`+0x524` 语义与新版不同）。
11. **结构体容量要随锚点同步扩**（报告 24 v12 事故）：`static HookDesc g_hooks[9]` 未随锚点扩到 10，安装循环写 `g_hooks[9]` 越界 32B，冲掉紧随的 `g_trampPage` 指针 → trampoline memcpy 到垃圾地址 → 游戏秒退。新增 hook 必须同步改数组容量。

### 五、换版本适配速查（★ 换客户端只看这节）

**背景**：不同版本/不同端地址全变，但**读法公式、hook 引擎、协议、宿主全套都能原样复用**；需要重找的只有「地址与函数锚点」。**我们不收裸地址**——每项都要附证据链。

**P0 加密体系四件套（万能钥匙，拿到它一切加密字段都能读）**
| 要什么 | 本版（ACT1）参考值 | 验收标准 |
|---|---|---|
| ① 加密表基指针全局变量 | `0x00CFD458`（值=ctx，ctx+0=容量 0x200000，baseA=*(ctx+17*4)） | 给出 ctx 构造函数反汇编（表分配大小） |
| ② 密钥全局变量 | `0x00CFD45C`（每次启动随机） | 给出密钥初始化函数（含 rand 混合；线索：搜立即数 `0xA1B2C3D4`） |
| ③ 槽解算器函数 | `sub_402030` | 完整反编译：校验公式+解密公式+失败分支 |
| ④ 槽注册器/字段登记 | `sub_901540`/`sub_9011D0` | 说明"全局变量→槽指针"怎么挂上 |

**P1 玩家对象 + 核心计数器**
玩家对象指针全局（ACT1=`0x00B75A14`，attach/清除写点）；HP/MP 槽偏移（`+0x1168`/`+0x1170`，黄金标准=游戏 GetHP thunk）；坐标偏移（`+0x13C/+0x140`）；角色归属偏移（`+0x30`）；被击计数器全局（`0x00B5ED28`，需唯一 ++ 点 + 完整门控链 + 唯一清零点）；评分对象 + 总评偏移（`0x00B5B410+932`）。

**P2 hook 锚点（若沿用 hook 路线；纯轮询可跳过）**
伤害数字生成咽喉（`sub_470ED0`，**参数语义逐一证实——a1-a3 是坐标不是对象**）；扣血结算（`sub_4748D0`）；状态 tick 调度器（`sub_4D10F0`）；通知分发器死亡分支（`0x4217CE`，jmp 进非 call，返回地址不可用）；播报层（`sub_4E6DA0`）；统一事件发送器（`sub_433890`）；**绝对不可 hook**（`0x790D93` E8 指令，只需报告位置）。
**交付格式三件套**：地址/偏移 + IDA 反编译或反汇编证据 + 一句话"怎么确认的"。入口前 16 字节反汇编必须给（判断能否安全 hook——**绝不可 E8/E9/JMP rel32 开头**）。

**P3 暴击数字对象（纯轮询路线，可后置）**
战斗核心单例 + 枚举链（ACT1=`0xB5DCE0` → +0x200010 → +0xB0 → vector）；伤害数字对象 vftable（`0x99D21C`，注意排除 RTTI 结构地址）；暴击动画指针偏移（`+0x1AC`）。

**无需重找、直接复用**：宿主 SorahkDFO 全套（协议不变即复用）；DLL 的 hook 引擎/汇编 stub/6ms 轮询框架/去抖子槽/共享内存协议；全部读法公式与方法论（加密解密/完整性校验公式结构、沿检测模式、"找游戏自身读路径"验证法）。

**评分等级映射（实机验证）**：`sub_1DD2100` 返回 0~8，**数字越低评价越高**——8=F、7=E、6=D、5=C、4=B、3=A、2=S、1=SS、0=SSS；结算时逐级触发（实机日志 8→6→5→4→3→2→1→0）。采集过滤条件必须 `lvl > 8` 才丢弃（写成 `lvl < 2` 会丢掉 SS/SSS）。

**评分点计算（`sub_1DD9B70`）**：`v5 = Σ(评分对象权重字段 × 场景槽字段)`，封顶 `6×sum`；若场景标志 `a3[52]` 成立则 **`v5 *= 5`（增益叠加）**；再乘全局倍率 `dword_4189A98`，最后 `sub_1DD4B90(v6, 18, v5)` 写入评分对象（事件 18）。

### 判定分发中心 sub_1E2D840（0x1E2D840，switch case 0~15）

### 加密双表算法（完整公式）
```
明文 = 存储值 ^ *(0x00CFD45C) ^ (表A + 4*idx)
  表A = *(*(0x00CFD458) + 17*4)；表B = *(*(0x00CFD458) + 18*4)（镜像冗余）
  idx = 槽描述符[+4]；槽[0] = 完整性标记
完整性： (密钥 ^ 槽[0]) - 槽地址 == 槽[1]
密钥 = 0xA1B2C3D4 ^ ((rand()<<16)|rand())，每次启动随机（sub_901E40）
读器： sub_418260（float）/ sub_402030（dword）；写器： sub_404B00（**DLL 禁用**）
```

## ⚠ 两版地址不可混用

新版（90US）与老版（ACT1）是**两个完全不同的客户端**：地址体系、评分系统构成、加密体系（新版二级查表 XOR vs 老版双表+运行时随机密钥）、hook 锚点全部不同。任何跨版套用地址都会失败。正确做法见第一部分第五节「换版本适配速查」。
