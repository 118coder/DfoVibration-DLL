## 二、架构：版本锚点深模块（本次重构的核心）

### 2.1 问题
原 DLL 把版本相关常量散落在 4 个文件（`hooks_old.c` / `dfovib_old.c` / `vib_protocol_old.h` / `hooks_old_asm.s`）约 **211 处**十六进制字面量里，移植 ACT5 要逐文件手改，漏一处即 hook 错地址 → 崩游戏。

### 2.2 方案
新建**唯一版本剖面模块** `DLL源码\vib_target_old.h`，用编译宏 `VIB_TARGET`（`1`=ACT1 / `5`=ACT5）集中全部版本相关常量：

```
vib_target_old.h  ──唯一版本剖面──  TGT_HOOK_* / TGT_HOOKLEN_* / TGT_SIG_* / TGT_STR_* / TGT_PLAYER_* / TGT_ENC_*
        ▲                                    │
vib_protocol_old.h(OLD_* 别名) ──────────────┤
hooks_old.c / dfovib_old.c(只引用符号) ───────┘
```

- **未定位哨兵** `VIB_ANCHOR_UNRESOLVED(0)`：hook 安装/轮询遇到 0 **显式跳过并写日志**，绝不静默装错地址。
- **安装期签名校验**：每个 hook 锚点带 8 字节期望签名，安装前 `memcmp`，不匹配→**拒绝安装**（把「错地址=崩溃」降级为「拒绝启动该 hook」）。
- **容量宏同源**：`VIB_HOOK_COUNT` 同时定义锚点表/数组/trampoline 页容量，结构性杜绝历史越界事故。
- **换版本**：只改 `vib_target_old.h` 一个 `#elif` 段，引擎/协议代码不动。

### 2.3 构建
```bat
DLL源码\build_old.bat      :: ACT1 剖面（默认，现网行为不变）→ release\DfoVibration_OLD.dll
DLL源码\build_act5.bat     :: ACT5 剖面(-DVIB_TARGET=5)      → release\DfoVibration_ACT5.dll
DLL源码\install_act5.bat "E:\Game\DNF-ACT5"   :: 部署为 DfoVibration_OLD.dll（宿主 auto_inject 认这个名）
```
回退：`copy /y 游戏目录\DfoVibration_OLD.dll.act1bak 游戏目录\DfoVibration_OLD.dll`。

## 五、ACT5 版本特化点（与 ACT1 的差异，改这些才会不一样）

| # | 差异 | 处理 |
|---|---|---|
| 1 | **伤害咽喉 cdecl 多一个前导参**：ACT1 `(a1,a2,a3,a4,a5)` → ACT5 `(Src,x,y,z,伤害=a5,标志=a6)` | 新增汇编 `vib_stub_13`（栈偏移整体 +4），复用同一 C 分派 `vib_dispatch_damage_font`；剖面宏 `TGT_STUB_DMGFONT` 按版本选 stub8/stub13 |
| 2 | **状态名是 UTF-16 宽串** | `safe_str_eq()` 改为剖面感知（`VIB_STR_WIDE=1` 时逐宽字符比较 ASCII 字面量），分发逻辑零改动 |
| 3 | **模块映像区变大**（含 nsn 段到 0x227e000） | `VIB_IMAGE_LO/HI` 剖面宏（堆指针判据用） |
| 4 | **玩家结构整体 +0x30**：坐标 `+0x13C/+0x140` → **`+0x16C/+0x170`** | `[pos]` 探针实测（走位时 600→1333→548 平滑变化）后填入 |
| 5 | **城镇玩家对象是另一个全局** | 副本 `dword_10B2FDC` / 城镇 `dword_10B2FE0`（`sub_576EA0` 成对管理，对应 ACT1 的 B75A14/B75A18 双源） |
| 6 | **播报层不是 `{2,3,5,6,7}` switch** | ACT5 按状态串匹配：`HK_STYLE/HK_TECHNIC` 的引用点落在 `sub_555D60`，其 `a2==6/7`（与 ACT1 同码） |
| 7 | **移动事件强度需提高** | ACT1 用 40；V3 宿主输出还要 ×pulse×gain 且被 4% 低强度抑制吞 → ACT5 改 **100**（`VIB_MOVE_STR`） |

## 六、无损与安全设计

1. **只读轮询**：坐标/HP/评分等一律纯读；加密字段读法只读不写（写路径会破坏完整性标记）。
2. **hook 安全性**：只 hook 普通指令开头（`first_insn_safe` 拒绝 E8/E9/EB/C3/C2）；变长 hookLen 由指令边界计算；trampoline 重放 + E9 回跳；`0x790D93`（E8 相对调用）**永久不安装**（历史卡死事故）。
3. **安装期签名校验**：8 字节期望签名 `memcmp`，不匹配拒绝安装（新版本客户端的保险）。
4. **未定位哨兵**：未定位锚点显式跳过 + 日志，不猜地址。
5. **hook 完整性自检**：60s 检查首字节是否仍为 E9。

## 七、排障记录：三个「DLL 对了但没震」的宿主侧原因

这三条都是**宿主配置/参数**层面，DLL 无法补偿，记录以免重复排查：

| 症状 | 根因 | 证据 | 处理 |
|---|---|---|---|
| 镜头震动不震 | ACT1 时代走 `VEV_KILL`；V3 宿主另有专用「镜头震动」通道（idx10, `VEV_SHAKE_SCREEN`） | `vibration.rs` 常量表 | **用户指定仍走「释放技能」**（`VEV_KILL`），已按此实现 |
| 评分点不震 | 宿主 `storm_mute_rank=true` + `storm_enabled=true`：**命中风暴期整族静音评分点系统**，而 STYLE/TECHNIC 恰在风暴期触发 | 宿主日志 `[STORM] 风暴期静音评分点系统` | 宿主 GUI 取消勾选「风暴期静音评分点系统」 |
| 移动不震 | ①「移动」滑块一度为 0（宿主日志 `rank11=0 s=0.000 -> off`）；② DLL 强度 40 → `move_level=0.4`，经 ×pulse(≤40%)×gain(≤45%) 后 ≈3.7% **低于宿主 4% 低强度抑制阈值**被归零 | 宿主日志 `[MV] str=40 rank11=100 s=0.400 -> active` 但仍无输出 | ①滑块拉满；②**DLL 强度 40→100**（v0.14） |

> 诊断方法固化：DLL 侧 `[f]/[sd]/[shake]/[die]/[mvB]/[move]/[pos]` 探针 + 宿主 `SorahkDFO_vib.log` 的 `[MV]/[INJ]/[STORM]/[GATE]/[DROP]`，两侧对齐即可把「用户感觉」翻译成「日志指标」。
