## 1. 项目目标与硬约束

- 给 **ACT5 老客户端**做手柄震动适配（官方受邀任务，无风险逆向已授权）。
- **硬约束 1：不改宿主软件**。DLL 只发同一套 `VibEvent` 协议（`Local\DfoVibrationShm` 环形队列），宿主零改动。
- **硬约束 2：震动参数全部归宿主 GUI**（用户铁律「参数归 GUI」）；DLL 只负责发正确类型的事件。
- **硬约束 3：不改写游戏字节之外的东西**；采用只读轮询 + inline hook（见 §6 安全设计）。
- ACT5 与 ACT1 **基址/结构全不同**（ACT1 地址仅作参考），必须逐项重定位——这是本项目的核心工作量。

## 3. 架构总览

```
游戏进程 DNF.exe (ACT5, 32位)
  DfoVibration_OLD.dll（注入加载）
    ├─ inline hook × 5（见 §5 锚点表）
    ├─ 无损只读轮询 collector（6ms）：移动坐标双源 / 加密字段探针 / 暴击数字
    └─ 写共享内存 Local\DfoVibrationShm（VibShm + 256KB VibRing, CAS 环）
          │
宿主 SorahkDFO-新UI版.exe（Rust）
  读共享内存 → vibration.rs 引擎合成 → XInputSetState 驱动马达
  GUI 全部滑块在此；**DLL 侧零 ini，参数全归宿主**
```

### 版本锚点深模块（本次重构核心）
`DLL源码\vib_target_old.h` 是**唯一的版本剖面**：所有随版本变化的常量（地址/偏移/状态名/hookLen/签名）按 `VIB_TARGET`（`1`=ACT1 / `5`=ACT5）集中在这一处。其余文件（`hooks_old.c`/`dfovib_old.c`/`vib_protocol_old.h`/`hooks_old_asm.s`）只引用符号，无版本字面量。

- **换版本** = 只改 `vib_target_old.h` 一个 `#elif` 段；
- **未定位哨兵** `VIB_ANCHOR_UNRESOLVED(0)`：安装/轮询遇 0 **显式跳过并写日志**，绝不静默装错地址；
- **安装期签名校验**：每锚点带 8 字节期望签名，`memcmp` 不符→**拒绝安装**；
- **容量宏同源** `VIB_HOOK_COUNT`：锚点表/数组/trampoline 页共用，结构性杜绝越界事故。

## 5. 事件 → 宿主通道映射（ACT5 版）

```
命中/受击/暴击/DOT/回复   sub_4ACC00       → VEV_FONT(10) + 标志位   → 飘字 6 个子滑块
评分播报 STYLE/TECHNIC    sub_555D60(a2=6/7)→ VEV_KILLPOINT(12)      → 「评分点」(rank idx0)
镜头震动                  sub_552CF0       → VEV_KILL(21)            → 「释放技能」(idx9) ★用户指定
怪物死亡                  notify38         → VEV_TARGET_DIE(2)       → 「怪物死亡」(idx14)
结算 VICTORY/RANK_UP…      sub_44D460       → VEV_RANKING(11)/FINAL_KILL(17)/CRIT_SHAKE(25)
移动（副本/城镇双源）      坐标轮询          → VEV_MOVE(23, 强度100)    → 「移动」(idx11)
```

**伤害标志位语义（实机确认，与 ACT1 同构）**：`0x01` 命中 / `0x02` 受击 / `0x04` 回复（宿主状态通道）/ `0x08` 状态 / `0x10` 特殊（暴击·破招·背击）/ `0x20` DOT；组合如 `0x11`=0x10\|0x01 暴击、`0x21`=0x20\|0x01 怪物 DOT。

**用户口径**：评分走「评分点」；镜头震动走「释放技能」；移动走「移动（持续震动）」。

## 6. ACT5 版本特化点（改这些才会不一样）

| # | 差异 | 处理 |
|---|---|---|
| 1 | 伤害咽喉 cdecl **多一个前导参**：ACT1 `(a1,a2,a3,a4,a5)` → ACT5 `(Src,x,y,z,伤害=a5,标志=a6)` | 新增汇编 **stub13**（栈偏移整体 +4），复用同一 C 分派 `vib_dispatch_damage_font`；剖面宏 `TGT_STUB_DMGFONT` 按版本选 stub8/stub13 |
| 2 | 状态名是 **UTF-16 宽串** | `safe_str_eq()` 剖面感知（`VIB_STR_WIDE=1` 时逐宽字符比较 ASCII 字面量），分发逻辑零改动 |
| 3 | 模块映像区变大（nsn 段到 0x227e000） | 剖面宏 `VIB_IMAGE_LO/HI` |
| 4 | 玩家结构 **+0x30**：坐标 +0x13C/0x140 → **+0x16C/+0x170** | `[pos]` 探针实测后填入 |
| 5 | 城镇玩家是**另一个全局** | 副本 `dword_10B2FDC` / 城镇 `dword_10B2FE0`（双源并行，走位逻辑原有） |
| 6 | 播报层**不是 `{2,3,5,6,7}` switch** | 改为按状态串匹配：`HK_STYLE/HK_TECHNIC` 的引用点落在 `sub_555D60`，其 `a2==6/7`（与 ACT1 同码） |
| 7 | 移动事件**强度需 100**（ACT1 用 40） | `VIB_MOVE_STR`（仅 ACT5）；因宿主移动输出还要 ×脉冲×增益并被低强度阈值截断 |
| 8 | **命中(0x01)合并窗 = 35ms**（定稿，移植自 ACT4 并实机调参） | 后期"疯狂震动"真源头 = 群怪同帧多目标 + **附加伤害同目标多条**。**剖面宏 `VIB_HIT_MERGE_MS`（ACT1=10 / ACT5=35）**。调参轨迹 20→25→**35ms**（用户实机试感定稿）。完整实测与判读见 **§9.5** |

**无损与安全**：只读轮询；只 hook 普通指令开头（`first_insn_safe` 拒绝 E8/E9/EB/C3/C2）；变长 hookLen 指令边界对齐 + trampoline 重放 + E9 回跳；`0x790D93`（E8）永久不装；安装期签名校验；未定位哨兵；60s hook 完整性自检。

```
[hook] target=ACT5 anchors=13
[hook] idx=0 OK 0x0044D460 len=7
[hook] idx=1 OK 0x00555D60 len=6
[hook] idx=8 OK 0x004ACC00 len=5
```

- 出现 `sig mismatch -> REFUSE` = 地址与签名不符（换版本/地址错），是**保护生效**不是失败。
- `mv=` 是移动事件计数（走路时应在涨）；`hm=` 是被**命中合并窗**（25ms）吞掉的 0x01 条数，`font a=` 是实际发出的 0x01 数——压缩比 = `font a ÷ (font a + hm)`。
- `hev/hgrp` 是命中分组探针（每 30s 窗口）：**`hev==hgrp` 说明 0x01 每目标每次一条**，合并窗只合并 AoE 群怪、不会吞同目标连段（安全）；若 **`hev>hgrp`** 则存在同帧同目标多条（如后期附加伤害），此时应把命中窗换成 `(tick,obj)` 去重（改动已就绪：`vib_hit_probe` 的计数逻辑即去重逻辑）。

**部署前提**：宿主要以 **`DNF.exe`** 进程名匹配注入；游戏目录里若有两个 exe，启动 `DNF.exe`（不是带空格的 `DNF ACT5.exe`）。宿主目录若无 `DfoVibration_OLD.dll`，它会去 DNF.exe 所在目录找。

| `tick … mv=… hm=… hev=… hgrp=… hrev=` | 移动事件数 `mv=`；命中合并窗吞掉的 0x01 条数 `hm=`（压缩比 = font a ÷ (font a + hm)）；`hev=`=纯 0x01 原始条数、`hgrp=`=(同帧,同目标)去重后命中数、`hrev=`=**跨帧**同目标重复(<200ms)数（均为**每 30s 窗口**）。**判读：`hev==hgrp` → 无同帧同目标重复；`hev>hgrp` → 有（ACT5 实测出现，ACT4 从未出现，见 §6#8）；`hrev>0` → 存在窗口外的同目标重复（含合法多段连击，**要区分附加伤害需做穿/不穿装备 A/B**）** |

**宿主侧**（`E:\网页小工具\DfoVibration V3版本\SorahkDFO_vib.log`）：
`[INJ]`（注入）`[MV]`（移动决策：str/rank11/s/active|off）`[GATE]`（总开关）`[DROP]` `[STORM]`（命中风暴）`[FLUSH]/[CARRY]/[HITCAP]`；`[vib] RANK pulse` 走 stderr。

**两侧对齐**：DLL 用 `GetTickCount`(开机 ms)，宿主用 UNIX epoch u32；对齐前先归零相对轴。

## 9.5 命中合并窗定案（穿/不穿附加伤害装备 A/B 实测，2026-09-13）

**起因**：用户觉得 ACT5 比 ACT4"更震"，怀疑 ACT5 新增的**附加伤害**会让同一次攻击对同一目标多报伤害数字 → 多出 0x01。

**手段**：DLL 加命中分组探针 `vib_hit_probe(obj=咽喉第1参, tick)`，tick 行输出三个量：
`hev`=纯 0x01 原始条数、`hgrp`=(同帧,同目标)去重数、`hrev`=跨帧同目标(<200ms)重复数；
`VIB_HIT_PROBE=2` 时另打 `[h] t= ep= obj= a5= DUP/REV` 明细（诊断期用，**定稿已关**）。

**四组对照**（用户实机；日志行带 epoch，按时间分箱）：

| 本地时间 | 场景 | 同帧同目标 DUP | 同目标间隔<25ms | 25–60ms（逃出窗） | >200ms |
|---|---|---|---|---|---|
| 04:57 | 不穿附加装 · 单怪 | **0** | 0 | 0 | — |
| 04:59 | 穿附加装 · 单怪 | **0** | 0 | 0 | — |
| 05:00–05:01 | **穿附加装 · 群怪** | **53** | **95（55.6%）** | 5（2.9%） | 45 |
| 05:02–05:03 | 不穿附加装 · 群怪 | **0** | 0 | 0 | 38（100%） |

**结论**：
1. **附加伤害被证实**：只有「穿附加装」出现同帧同目标重复（DUP=53）；「不穿」DUP=0、同目标重复**全部 >200ms**（正常一刀一刀）；单怪两组零重复。
2. **但大部分被合并窗吸收**：穿装 171 次同目标重复里 **95 次（55.6%）间隔 <25ms** → 落在窗内，不产生额外震动。
3. **仅约 3% 逃出窗**（5 次/30s 窗落在 25–60ms）；另有 26 次在 60–200ms（含附加伤害与正常多段，**纯时间判据不可分**）。
4. 量级为每 30s 多 5–30 次，**不足以解释"明显更震"**；主因判断为宿主配置（用户排查期关掉了「风暴期静音评分族」+ 把滑块拉满）。

**定案**：`VIB_HIT_MERGE_MS = 35`（20 → 25 → **35ms** 逐步试感，用户确认手感 OK 且未吞连段）。
**风险点**：ACT4 实测同目标连段最小 **31ms**，35ms 已贴近边缘；若日后极速连段出现掉段，回调到 30ms 即可（只改剖面一个宏）。

**tick 行判读口径**：压缩比 = `font a ÷ (font a + hm)`；`hev==hgrp` 无同帧同目标重复、`hev>hgrp` 有（附加伤害）；`hrev>0` 存在跨帧同目标快速重复（含正常连攻，需配合穿/不穿装对照区分）。

## 12. 流程纪律（vib-mod 精简，务必遵守）

1. **一次一事四步闭环**：patch → 构建 → **字节级验证** → 部署，四步不拆开；失败即停在此步。
2. **数据先于假设**：语义不明的字段先加节流探针实测标定，再进判定集（本项目 `[f]/[sd]/[shake]/[die]/[mvB]/[pos]` 都是这个套路）。
3. **铁律**：绝不 hook E8/E9/JMP rel32（trampoline 重放会崩）；hook 目标入口前 16 字节必须给反汇编证据；新增 hook 必须同步锚点表/签名/容量宏。
4. **版本与备份**：每版 DLL 入 `release_backup\`；部署前查目标进程；**绝不删除/覆盖用户正在运行的文件**。
5. **验收**：用户实机 + 日志闭环双满足才标「稳定版」；分职业（近战/远程）、分场景（城镇/副本）验证。
